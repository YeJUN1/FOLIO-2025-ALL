### 1.6 GLB 物理体命名约定：physical 根节点与 cuboid 碰撞体 scale 全尺寸

游戏物理体命名约定（Objects.js getFromModel + Physics/Physics.js 实现）：

- GLB 根节点名含 `physical` 即自动创建刚体，`fixed/dynamic/kinematicPositionBased` 字样决定类型（无字样默认 fixed）
- 子节点名以 `cuboid/hull/trimesh/tube/ball` 开头即解析为碰撞体并从场景移除该节点
- **cuboid 节点 scale 需填包围盒全尺寸**，游戏侧取 `scale*0.5` 作为 Rapier 半尺寸
- fixed 刚体会用 body 的平移/旋转覆盖 visual 变换，传入 physicalDescription 的 position/rotation 必须与模型一致
- scripts/hunyuan/process.js 据此自动注入 `<key> physical fixed` 根名与 cuboid 子节点

### 1.7 混元3D 自动造景流水线架构与用法

（2026-09-30 落地，mock 全链路已验证）

- 生成端 scripts/hunyuan/：

  - `generate.js`：调混元专业版提交/轮询/下载，state.json 断点续跑，支持 --mock/--force/--only/--list；原始产物落 resources/hunyuan-raw/（gitignore）

## 2. 经验教训

### 2.1 缺陷坑

#### 2.1.1 gltf-transform 读写 draco 模型的两个陷阱：写回保留压缩与 decoder 未注册报错

- **写回残留**：读取 draco 压缩 GLB 时注册了 ALL_EXTENSIONS + draco decoder → 写回自动保留 `KHR_draco_mesh_compression`（普通版"未压缩"约定被破坏）。修复：写前对 `doc.getRoot().listExtensionsUsed()` 中 `instanceof KHRDracoMeshCompression` 的实例调用 `.dispose()`
- **decoder 未注册**：报 `Cannot read properties of undefined (reading 'DT_FLOAT32')`。修复：`.registerDependencies({'draco3d.decoder': await draco3d.createDecoderModule(), 'draco3d.encoder': ...})`
- **降噪**：`new Logger(Logger.Verbosity.WARN)` 可消除 prune 日志噪音
- 适用边界：任何"读压缩模型 → 修改 → 导出未压缩版"的 gltf-transform 脚本（如 scripts/hunyuan/process.js）

### 2.2 工具经验

#### 2.2.1 腾讯云计费排查：GetCallerIdentity 核对密钥所属账号

- **使用场景**：云 API 反复报“资源不足/积分已用尽/无权限”，但控制台显示资源与配额正常时
- **方法**：用 sts:GetCallerIdentity 查密钥所属 UIN 与身份 ARN，与控制台右上角「账号信息」的账号 ID 比对；不一致即说明密钥与控制台资源不在同一账号下（同一人不同登录方式可能是多个独立账号、UIN 各不相同）
- **注意**：该接口无需额外业务授权，是低成本的鉴权/身份自查手段；控制台显示正常不代表密钥所属账号的状态
- 适用边界：任何“控制台正常但 API 异常”的计费/权限类报错

## 3. 开发规范

### 3.1 外部 GLB 模型集成流程（资源注册/材质转换/物理落地）

（已验证）1) 模型放入 static/ 子目录；2) 在 Game.js 第二批资源列表注册 `[key, 路径, 'gltf']`；3) 新建 World 模块并用 game.objects.add/addFromModel 加入场景，默认 updateMaterials:true 会将 MeshStandardMaterial 转为项目 MeshDefaultMaterial（保留 map/color，丢失 metalness/roughness，自带 reveal/阴影效果）；4) 用 game.RAPIER.Ray + physics.world.castRay 向地面或家具表面发射射线获取高度，实现精确落地/落座；5) type:'fixed' 的物理体会将 visual 的 position/rotation 覆盖为刚体值，必须在 physical description 中提供相同 position/rotation；6) 摆放在动态物理物体上时用纯视觉对象（不给物理体），避免物理冲突；7) 调试时 URL 加 #skip 可跳过开场等待并四倍速；坐标可解析对应 GLB 的节点 translation/rotation 获得；8) 大模型（约 80MB）用 `node scripts/compress.js static/子目录` 生成 Draco+KTX2 压缩版。

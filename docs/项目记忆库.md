### 1.6 GLB 物理体命名约定：physical 场景名与 cuboid 直接子节点（scale 全尺寸）

游戏物理体命名约定（Objects.js getFromModel + Physics/Physics.js 实现）。2026-10-01 修正关键细节：判定依据是「传入 addFromModel 的模型自身 .name 含 physical」，按接入方式分两类——① 整场景加入（如 Garden.js 传 gltf.scene）：physical 必须命名在 glTF **场景名**上（THREE 的 gltf.scene.name 取自 scenes[0].name），且碰撞体节点必须是场景的**直接子节点**；② 逐子节点加入（Area.js/Scenery.js 传 child）：命名在对应节点上。

- `fixed/dynamic/kinematicPositionBased` 字样决定类型（无字样默认 fixed）
- 碰撞体检测只扫描模型的直接子节点，名称以 `cuboid/hull/trimesh/tube/ball` 开头即解析并从场景移除
- **cuboid 节点 scale 需填包围盒全尺寸**，游戏侧取 `scale*0.5` 作为 Rapier 半尺寸
- fixed 刚体会用 body 的平移/旋转覆盖 visual 变换，传入 physicalDescription 的 position/rotation 必须与模型一致
- scripts/hunyuan/process.js 已按此实现：`scene.setName('<key> physical fixed')`（仅 cuboid 时带后缀）+ cuboid 直接挂场景

### 1.7 混元3D 自动造景流水线架构与用法

（2026-09-30 落地 mock 验证；2026-10-01 首次真实端到端验证完成；2026-10-03 顶层 scale 与 v2 重生成）

- 生成端 scripts/hunyuan/：
  - `manifest.json`：资产规格书（key/name/prompt/normalize/rotationFix/collider，30 项由 enabled 控制）
  - `generate.js`：调混元专业版提交/轮询/下载，state.json 断点续跑，支持 --mock/--force/--only/--list；原始产物落 resources/hunyuan-raw/（gitignore）
  - `process.js`：规范化（dedup/prune → 压平层级 → rotationFix → 按 normalize 轴等比缩放 → Pivot 归零底面中心 → 减面（meshoptimizer，weld + simplify，默认 ratio 0.05 / error 0.002）→ 贴图压缩（sharp，最大 1024²，无 alpha 转 JPEG q85、有 alpha 保留 PNG）→ 命名 glTF 场景为 `<key> physical fixed` 并挂 cuboid 直接子节点 → 材质唯一命名（防跨资产撞名串用）→ 导出 static/garden/<key>.glb）；--compress 用 gltf-transform CLI 出 `<key>-compressed.glb`；减面/贴图参数可由 manifest.defaults.simplify / defaults.texture 或资产级同名字段覆盖，资产级置 false 可禁用（动因与实测见 1.10、2.1.5）
  - `build.js`：npm run garden:build 一键串联 generate→process 并透传参数
- 游戏端 sources/Game/World/Garden.js：读 static/garden/scene.json（origin+scale+objects 为布局唯一数据源）→ resourcesLoader 懒加载（按 VITE_COMPRESSED 选后缀）→ 物理射线贴地 → addFromModel 创建 fixed 物理体；#debug 面板可显隐与微调 origin
- **顶层 scale（2026-10-03 新增）**：scene.json 支持顶层 `scale` 字段做整体等比缩放（花园 diorama 最终放大 5 倍）。Garden.js 会同时作用于：① 视觉 model.scale；② objects[].position 相对偏移（乘 scale）；③ 物理碰撞体——因 Objects.getFromModel 只读碰撞体子节点的**局部** scale/position（不含 model.scale），故 addItem 在 addFromModel 前把 cuboid/tube/ball 等「尺寸驱动」子节点的局部 scale 与 position 预乘缩放向量烘焙进去，保证物理体与视觉一致（trimesh/hull 为顶点驱动暂不支持）。资产 GLB 本身保持真实尺寸不改 manifest.normalize
- 新增资产 = manifest 一条 + scene.json 一条，零代码改动；密钥在 .env 的 TENCENTCLOUD_SECRET_ID / TENCENTCLOUD_SECRET_KEY
- **重生成已有资产（2026-10-03 新增，pavilion v2 实践）**：① 旧版先备份 `resources/hunyuan-raw/backup/<key>-v1-<日期>.glb`；② 新产物覆盖 `resources/hunyuan-raw/<key>.glb`；③ 更新 manifest（prompt/notes）与 state.json 时间戳；④ 仅跑 `node scripts/hunyuan/process.js --only <key> --compress` 覆盖 `static/garden/<key>.glb`（及压缩版），游戏端零改动
- **物理查询刷新（2026-10-03 修复）**：Garden.addItem 在创建物理体后调用 `this.game.physics.world.queryPipeline.update(this.game.physics.world.colliders)`——Rapier 查询管线仅在 world.step() 重建，同一同步循环内新建碰撞体对 castRay 不可见，不刷新会导致后摆放资产贴地射线穿透刚建好的底座而沉底（缺陷坑详见 2.1.4）
- 真实验证补充（2026-10-01，moonGate/taihuRock/pavilion）：云 API 积分耗尽时经官网网页版生成，state.json 标记 engine:'web'、status:'DONE'，仅跑 process.js；AI 生成实际尺寸普遍远小于 prompt 规格（原始高 0.72~0.95m vs 目标 2.2~3.0m，归一化缩放 1.37~3.15 倍），normalize 是必需环节；游戏内 3 items 位置正确、太湖石 fixed 刚体对位、控制台零错误

### 1.8 吃鸡式鼠标视角架构：指针锁定 + 准星中心拾取 + 拖拽降级

（2026-10-05 落地，View.setMouseLook()，默认视角模式 MODE_DEFAULT 生效）

- 进入：在画布上快速单击（与按下点位移 ≤8px，且未悬停交互点、无弹窗/菜单/过场）时调用 `canvasElement.requestPointerLock({unadjustedMovement:true})`，失败自动回退普通锁定；ESC 由浏览器释放；打开弹窗/菜单自动 exitPointerLock（ticker.wait 后再挂 modals/menu 事件，因 View 构造时二者尚未创建）
- 视角：锁定后 mousemove 的 movementX/movementY 直接改 spherical.theta（偏航，绕 focusPoint 环绕）与 spherical.phi（俯仰，限制 0.04π~0.47π），灵敏度 0.0025 rad/px，theta 归一化到 [-π,π]
- 准星：锁定期间 html 加 `is-pointer-locked` 类显示中心准星（.js-crosshair，crosshair.styl）；RayCursor 锁定期间改从屏幕中心 NDC 拾取，命中交互点时准星加 `is-intersecting` 放大；View.update 在锁定期间每帧重测拾取
- 降级：指针锁定不可用（pointerlockerror / promise 拒绝，如部分嵌入式预览环境）时自动切换为按住左键拖动转视角（dragActive），期间抑制 viewMapPointer 的地图平移，鼠标松开/窗口失焦即结束
- 未锁定时保留原有交互（单击交互点、左键拖动平移、滚轮缩放）；相关文件：sources/Game/View.js、RayCursor.js、sources/index.html、sources/style/crosshair.styl

### 1.9 原版性能优化体系（混元模型引入前的基线）

（2026-10-06 逐文件核实登记；用途：混元3D 资产性能对比与优化参照；详细展开版见 `docs/3D性能与内存优化.md` 第 2 节）

- **资产管线**（scripts/compress.js）：GLB 经 gltf-transform 做 draco 量化压缩（edgebreaker；position 12bit / normal 6bit / texcoord 6bit / color 2bit）；纹理压 KTX2（etc1s q255 或 uastc，按路径 preset，单通道 --swizzle r001）；UI 图转 WebP（sharp q80）；全场景低多边形共用一张 palette 调色板纹理上色（Materials.createPalette），材质集中保存复用
- **渲染**（Rendering.js / View.js / Viewport.js）：Three.js WebGPURenderer + TSL 节点材质；pixelRatio 上限 1.5；相机 fov 25 / near 0.1 / far 200；sortObjects=false 且用 renderOrder 自定义排序；antialias 仅 pixelRatio<2 时开启
- **后处理分级**：bloom mips 高质量 5 / 低质量 2；cheapDOF 低质量直接绕过；水面（WaterSurface.js）用单个 PlaneGeometry(1,1,1,1) + hashBlur(screenUV) 屏幕空间假倒影，无真实反射
- **阴影**（Ligthing.js）：仅一盏方向光；shadow map 1536/512 分级；阴影相机范围随玩家 optimalArea.radius 动态设定；normalBias 0.1 / bias -0.001 调优
- **GPU 化动画**：草地 78,400 根 = 单 mesh，顶点只存 xz，形状与风全部 TSL 顶点着色器生成（Grass.js）；树叶 2^7~2^11（Leaves.js）、雨 2^11（RainLines.js）、雪、闪电粒子均用 instancedArray + TSL 在 GPU 模拟，CPU 无逐帧粒子计算；天空为程序化 backgroundNode（Fog.js），无天空盒纹理
- **实例化**（InstancedGroup.js）：灯柱 / 灯笼 / 砖块 / 长椅 / 栅栏 / 爆炸箱 / 饼干 / 保龄球瓶 / 风扇等 9+ 类对象；仅 reference.needsUpdate 时才重写 instanceMatrix
- **质量分级**（Quality.js）：移动端 UA 自动降至 level 1，Options 面板可切换 High/Low；分级联动阴影贴图 / bloom mips / DOF / 水面模糊 / 粒子数量
- **物理**：Rapier WASM；碰撞体只用 cuboid / ball / cylinder 等简化形状；fixed 物体 sleeping:true 预眠；角色/车辆未激活时 body.setEnabled(false)
- **架构**：15 阶段优先级 tick 调度（Ticker.js）；threejs-override.js 覆写 Object3D.copy 跳过 userData 深拷贝；关键资源 index.html preload（palette.ktx、respawns 等 4 项）+ ResourcesLoader 缓存 Map + Garden 懒加载；resize 立即 setSize + 400ms 防抖 throttleChange 处理昂贵重建

### 1.10 混元高模性能优化：资产减面 + 贴图压缩 + 运行时参数（2026-10-06 实测）

（详细展开版（数据表/内存账本/验证流程/方法论）见 `docs/3D性能与内存优化.md`）

背景：园林 21 件混元资产（各约 50 万三角形、3×4096² PNG）使场景达 2697 万三角形，每帧再乘 2（主画面 + 阴影贴图各渲一遍），Mac M 系列 16G 实测 20.6 FPS、鼠标事件卡顿。

- **实测对照（定位瓶颈）**：关闭阴影 20.6→47 FPS（+128%，最大头，顶点吞吐双份）> pixelRatio 2→1（+14%）≈ 移除 DOF（+15%）
- **资产级修复（process.js 新增两步，默认参数，manifest 可覆盖/禁用）**：
  - simplify（meshoptimizer）：weld(0.0001) → simplify({ratio: 0.05, error: 0.002})，50 万面 → 2.5 万面（error 为相对模型半径的比例）
  - compressTexture（sharp）：最大 1024²，无 alpha → JPEG q85（有 alpha 保留 PNG），单件贴图 31.5MB → 0.3MB
  - 效果：21 件资产 GLB 40~70MB → 1~4MB（目录 1.2GB → 47MB）；-compressed（Draco）已全量重新生成
- **运行时参数（三处）**：Viewport.pixelRatioMax 2 → 1.5；cheapDOF repeats 25 → 12；Lighting 阴影贴图 2048 → 1536（level 0，level 1 维持 512）
- **物理微优化**：Physics.update 水下阻尼改为状态切换时写入（原实现每帧对全部刚体无条件 setLinearDamping/setAngularDamping，是 WASM 跨界调用开销）
- **实测结果**：出生点与花园内均 60 FPS（打满 vsync）、帧时间 16.12ms、每帧渲染三角形约 510 万（含阴影/后处理多 pass）、场景静态三角形 339 万（-87%）；截图目检无破面、无贴图异常（园林单件 25k~72k 面）
- 验证方式：浏览器子代理 physicalVehicle.moveTo() 传送取景 + rAF 帧率采样 + 截图目检；dev 下 static 批量变更会触发 vite-plugin-restart 反复重启（见 2.2.3），页面须硬刷新后再验证
- 遗留：SpidermanRig 雕像约 150 万面（非园林资产，本轮未减面），后续如需进一步压榨可另行走减面流程

#### 2.1.1 gltf-transform 读写 draco 模型的两个陷阱：写回保留压缩与 decoder 未注册报错

#### 2.1.2 process.js 包装节点承载 physical 命名不生效：须命名 glTF 场景本身

- **Bug 类**：资产规范化脚本在 glTF 场景内新建包装子节点并命名 `<key> physical fixed`，期望游戏加载后自动创建固定刚体，结果不生效

#### 2.1.4 Rapier 查询管线仅在 world.step() 重建：同帧 castRay 穿透新建碰撞体致物件沉底

## 3. 开发规范

### 3.1 外部 GLB 模型集成流程（资源注册/材质转换/物理落地）

（已验证）1) 模型放入 static/ 子目录；2) 在 Game.js 第二批资源列表注册 `[key, 路径, 'gltf']`；3) 新建 World 模块并用 game.objects.add/addFromModel 加入场景，默认 updateMaterials:true 会将 MeshStandardMaterial 转为项目 MeshDefaultMaterial（保留 map/color，丢失 metalness/roughness，自带 reveal/阴影效果）——注意转换结果按材质名跨对象缓存共享，**材质名必须全局唯一**，不同资产间同名会串用贴图（见 2.1.3）；4) 用 game.RAPIER.Ray + physics.world.castRay 向地面或家具表面发射射线获取高度，实现精确落地/落座；5) type:'fixed' 的物理体会将 visual 的 position/rotation 覆盖为刚体值，必须在 physical description 中提供相同 position/rotation；6) 摆放在动态物理物体上时用纯视觉对象（不给物理体），避免物理冲突；7) 调试时 URL 加 #skip 可跳过开场等待并四倍速；坐标可解析对应 GLB 的节点 translation/rotation 获得；8) 大模型（约 80MB）用 `node scripts/compress.js static/子目录` 生成 Draco+KTX2 压缩版。

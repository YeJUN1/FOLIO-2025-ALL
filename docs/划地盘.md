## 划地盘规则：先到先得，后划者只能圈空地

**已经被人圈走的地，后来的人不许再圈；只能在剩下的空地上画。**

1. **先划者优先**：登记册里已有的范围属于先划者，后划者不得覆盖、改写，也不得把别人的地整块记成自己的。
2. **后划者收边**：新地块与任何已登记地块的交集必须为空——可以共边、贴边，但不能有面积交叠。碰到冲突只能改自己的边界往回收，不能要求先划者让地。
3. **改旧界要先协商**：确实需要调整先划者的边界时，必须在本文档写清「谁同意 / 改到哪 / 为什么」，双方确认后才能改。
4. **登记前自检**：把新矩形的 x、z 区间与登记册逐块求交，只要 `x 交叠宽度 > 0 且 z 交叠高度 > 0` 就是不合格，必须改到不相交为止。
5. **登记三要素**：世界坐标范围（min/max）、换算依据、代码落点（哪个文件生效），缺一不算登记成功。

### 2026-10-25：围栏加碰撞箱 + 南边开门（对齐唐一琳的门）

> 需求：把围栏加入碰撞箱，并删除一块围栏当做门，和唐一林的围栏门对应位置差不多；从门里进入，仍然要被导弹锁定。

- **碰撞**：`Territory.addCollider()` 给每件栏杆配一个 `fixed` cuboid，尺寸/中心/转角都按件自己的包围盒（`bounds` × scale，中心偏移也乘 scale，所以件的原点不必在几何中心）。实测件外形 **2.232 宽 × 1.058 高 × 0.176 厚**（半尺寸 1.116 / 0.529 / 0.088），底面贴在件的落地高度上。
  - 走 `game.physics.getPhysical()` 而**不走 `objects.add()`**：后者对 fixed 物体每帧把 visual 位置回写到 body 上，会覆盖掉射线贴地的结果；而且静态件不该出现在 `objects.list` 里被船的撞物遍历扫到。
  - 逐件建箱，所以「跳过一件」同时就少了视觉和碰撞，不会留下隐形墙。
  - `territory.json` 的 `colliders: false` 可整圈关掉，退回纯视觉。
- **门**：`gate { x, z, width }`，判据是件中心到门中心的圆距离 `< width/2` 就不摆（`isInGate()`）。没配 `gate` 就是完整一圈（取消了早先「没配就默认在北边中点开洞」的隐藏兜底，那会让范围一改就莫名多个门）。
  - 门开在南边 `z = 28.7`、`x = 55`、宽 6m：唐一琳 `PandoraFence.js` 的 `gate = { x: 55, width: 6 }` 在他北边 `z = 27.4` 那条边上，两家门**同一横坐标、相隔 1.3m 对口**。

- **贴地射线必须过滤 `floor` 分类**：`getGroundElevation()` 加 predicate `collider.collisionGroups() === physics.categories.floor`，否则后摆的件会打在前一件的箱顶上，越摆越高（`TerritoryDefense` 里同一个坑）。

### 一、结论：这个框在哪

#### 世界坐标（3D 场景，单位 = 米）

```js
{ west: -96, east: -13.5, north: 23, south: 80 }   // 宽 82.5 × 高 57
```

整个场景是 `terrain.size = 192` 的方形岛，原点在岛中心，所以坐标范围是 `±96`。
`x` 向东为正、`z` 向南为正（对应地图上的「向下」）。

| 边 | 方程 | 说明 |
| --- | --- | --- |
| 北 | `z = 23`，`x ∈ [-96, -13.5]` | 中西部空地（`z ≤ 22`）南侧，留 1 米间隔 |
| 东 | `x = -13.5`，`z ∈ [23, 80]` | 向东扩 20 米，落在中西部东南侧的开阔地 |
| 南 | `z = 80`，`x ∈ [-96, -13.5]` | 地图西南部，向南扩 8 米 |
| 西 | `x = -96`，`z ∈ [23, 80]` | 正好是地图左边界，整条在 1.5 米深的海里 |

圆角半径 `2.25` 世界单位 —— 这个值是为了跟地图标注框对齐（`map.styl` 里 `.fenced-zone` 的 `border-radius: 12px`，在 1024px 宽的容器上折算成世界单位就是 `12 / 1024 × 192 ≈ 2.25`）。

#### 换算到各套坐标系

统一用这一个线性映射（`Map.js` 的 `worldToMap` 就是它）：

```text
归一化 u = x / 192 + 0.5
归一化 v = z / 192 + 0.5        // v 就是 CSS 的 top%，向下为正
```

| 坐标系 | 西北角 | 东南角 |
| --- | --- | --- |
| 归一化 0~1 | `(0, 0.6198)` | `(0.4297, 0.9167)` |
| 2048×2048 俯视图 | `(0, 1269)` | `(880, 1877)` |
| 751×753 地图截图 | `(0, 467)` | `(323, 690)` |
| CSS 百分比 | `left 0% / top 61.98%` | `right 57.03% / bottom 8.33%` |

### 二、这些数字是怎么量出来的

1. **提取红笔轨迹**：用 `sharp` 读截图原始像素，只保留 `r > 200 && g < 45 && b < 45` 的像素。
   阈值一定要收紧，否则红白路缘石会被一起检出（第一版就糊成了 10 万噪点）。
   剩下的轨迹是个**圆角矩形**，不是椭圆：像素 `x ∈ [0, 255]`、`y ∈ [245, 444]`。
2. **校验坐标映射**：不要凭肉眼估像素。图里那 12 个白色菱形 pin 是已知世界坐标的
   （`respawns.getByName()` + `Map.js` 里每项的 `offset`），做连通域检测找出 12 个菱形中心，
   再按 `worldX = (px / W - 0.5) × 192` 反解，逐点比对误差全部 < 2 单位 → 证明映射成立，
   且那张截图正好覆盖 `±96` 全图。
3. **2026-10-21 调整范围**：原框 `z ∈ [-33, 16]` 与舒雯（`z ≤ -16.2`）、中西部（`z ≤ 22`）重叠，
   先沿 `+z` 平移 56 米得到 `z ∈ [23, 72]`；再把东边界从 `-33.5` 扩到 `-13.5`（+20 米），
   最后南边界从 `72` 扩到 `80`（+8 米），最终 `82.5 × 57`，与其余 5 块地均不重叠。

#### 重烤流程

```bash
node scripts/fence-enclosure.mjs --strict --preview   # 出走向图 scripts/tmp-fence-preview.png 核对
node scripts/fence-enclosure.mjs --strict --write     # 写 sources/data/fenceEnclosure.js
```

- `--strict`：栏杆一律压在画线上，不为避让赛道挪位或留缺口
- 不加 `--strict`：压在赛道上的退到路肩，躲不开的删掉留成路口

### 四、当前摆法（strict）

```text
画线采样 128 片 → 深水跳过 45 片 → 实际摆放 83 片
其中 20 片正压在柏油路面上（strict 的预期行为，压线处的赛道被封死）
```

单片栏杆长 `2.14`（碰撞体 half-extent 1.067 × 2），所以画线按 2.14 的间距切片；
`y = 地面高度 + 1.04`，地面高度取自 `static/terrain/terrain.glb` 的 129×129 顶点双线性采样
—— 这份几何就是 `Floor.setPhysical` 建物理 heightfield 用的那份，所以离线高度和运行时碰撞地面严格一致。

#### 两个已知取舍

1. **西边不围**：`x = -96` 整条在 1.5 米深的海里，立上去栏杆几乎全在水下（顶栏只露出水面约 5cm）。

2. **赛道被横穿处封死**：有 20 片压在既有柏油路面上，
   栏杆是 fixed 碰撞体撞不倒。已确认 18 个 respawn 点没有一个落在区内，所以地图传送不会把自己关在里面。

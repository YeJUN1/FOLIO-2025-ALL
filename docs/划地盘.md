## 2026-10-13：左下角红框的坐标标定

> 需求：用某种坐标（经纬度或其他方式）表示地图截图左下角红框范围，作为"我的地盘"。

### 依据：游戏内坐标系统

- `sources/Game/Map.js` 的 `worldToMap()`：地图为线性映射，`mapX = x / 192 + 0.5`、`mapY = z / 192 + 0.5`（z 越大越靠图下方）
- `sources/Game/Terrain.js`：`this.size = 192`，即世界坐标 x/z 各覆盖 **[-96, 96]**，地图图中心 = 世界原点 (0, 0)
- 换算公式（地图百分比 ↔ 世界坐标）：`x = (pctX - 50) × 1.92`，`z = (pctY - 50) × 1.92`
- 验证方式：`scripts/tmp-map-calibrate.mjs` 解析截图（1808×1806）定位红框与白色 pin 像素，与 `static/respawns/respawnsReferences.glb` 的坐标反推吻合（如 Circuit (-40.8, -44.4) ↔ 左上环路 pin、Altar (74.8, -14.1) ↔ 右侧 pin）

### 红框范围（三种表示法）

| 表示法 | 范围 |
| --- | --- |
| 世界坐标（游戏内可直接用） | x ∈ [-95.6, -73.8]，z ∈ [74.9, 96]，约 21.8m × 21.1m |
| 地图百分比（对应 map-day.webp 显示区域） | left 0.2% → 11.6%，top 89.0% → 100% |
| 伪经纬度（[-96,96] 线性映射到全球经纬度，图上为北） | 中心 N 42.2° W 138.0° |

### 备注

- 红框基本落在**海面**上，框内只有一座小岛；若需要圈可通行的陆地，应向东北方向挪动后重新标定。

## 2026-10-14：右下角红框标定 + 用栏杆围起来

> 需求：把地图**右下角**红框（含一座橙色建筑的那块地）用多个外部 glb（`30954c88932dfcdda0babea299042f41.glb`，木板栏杆件）沿四周首尾相接围成一圈。

### 标定方法（比 10-13 更精确）

- 不再依赖地图方框边框像素（边框非纯色直线，检测不稳），改用**地图上 12 个白色 pin** 反解：
  - 用 PIL+numpy 按颜色阈值检测红框描边（描边色 ≈ RGB(239,59,36)）与白色 pin 中心（近白菱形，面积≈420px）
  - pin 世界坐标取自 `static/respawns/respawnsReferences.glb` 各 `respawn<Name>` 节点 translation，仅取 `Map.js setLocations` 列出的 12 个地点
  - 减去 `Map.js` 各地点的标签 `offset`（分数）后，对 `pixel = L + mapFrac·S` 做最小二乘拟合
- 拟合结果：地图方框像素 left=114.4 / top=3.7 / 边长≈1398（Sx≈Sy 完全正方形），**残差 RMS < 0.5px**
- 红框描边像素：left≈949 / right≈1506 / top≈894 / bottom≈1390

### 红框范围（右下角）

| 表示法 | 范围 |
| --- | --- |
| 世界坐标 | x ∈ [18.6, 95.1]，z ∈ [26.3, 94.4]，约 76.5m × 68.1m |
| 说明 | 右/下两条边基本贴地图边界（±96），框内为陆地+右下角海面 |

### 实现：数据驱动领地围栏（纯视觉）

- **减面件**：`scripts/territory-prepare.js` 把外部高模（≈9 万三角形 / 41MB / 3×4096² PNG）经 weld+simplify(meshoptimizer, ratio 0.02) 减到 **1 万三角形**、贴图压到 1024² JPEG → `static/territory/fence.glb`（0.52MB）；材质唯一命名 `territoryFence_0`（防串用，见记忆 2.1.3）
  - 该件压平层级后烘焙了节点旋转，成为**竖直木板**：宽(局部X)1.12 × 高(Y)0.53 × 厚(Z)0.09，**底面已在 y=0**
- **摆放**：`sources/Game/World/Territory.js`（在 `World.js` step 1 注册）读 `static/territory/territory.json`：
  - 量出件长(局部X包围盒宽)×scale 作为间距，沿矩形四条边首尾相接排布；上下边 rotationY=0、左右边 rotationY=90°
  - 每件 `game.objects.addFromModel`（名不含 physical → 纯视觉无碰撞，玩家可穿过），用 physics 射线贴地（复用 `Floor.js` heightfield），落到海面时兜底到水面(-0.3)之上
  - `#debug` 面板 🚧 Territory 可显隐
- **配置**（`static/territory/territory.json`）：`territories[]` 里每一块地盘一个 `rect`（仍兼容只写顶层 `rect` 的旧文件）、每块自己的 `scale` / `overlap`、以及顶层的 `yOffset`、`minAboveWater`。改范围/密度只改此文件。重合的边只铺一次；`clipClearances` 会跳过穿过 `clearances` 的边段
- **验证**：dev 动态 `import('/Game/Game.js')` 取 `game.world.territory` → 140 件、bbox 精确等于 [18.6,95.1]×[26.3,94.4]、四边均有分布、y 在 [-0.25,0] 贴地、控制台无 Territory/fence/404/材质报错
- 性能：140 件共享同一几何(1万面)克隆 ≈ 140 万三角形/帧（含阴影翻倍），与现有园林量级相当；如需更省，调小 `scale` 增件数无益，应调大 `scale` 减件数或进一步降 `territory-prepare.js` 的 ratio

## Peter / peterzhang0528：我的地盘

Peter Zhang（GitHub `peterzhang0528`）把上面两块地盘和园林、竹篱、海岛说明之外的**剩余陆地**围了起来。栏杆仍是纯视觉，车可以穿过去。

世界范围 x、z 都在 [-96, 96]。z 越大越靠地图下方（南）。已有地盘一律不叠面积：和须翊恒、舒雯的边留出缝，避免两排栏杆叠在同一条线上。

### 怎么切的

高度来自 `static/terrain/terrain.glb`（129×129，水面约 y = -0.3）。y > -0.2 当成陆地。五块矩形盖住约 **99%** 的空闲陆地，深海和下面三处故意留白：

- **园林**在原点 (29, -45)、整体 scale 5，占地大约 x ∈ [-7.0, 62.9]、z ∈ [-78.3, -11.7]。它落在「北苑」内部，围栏在外围，最近的边也离开台面 **8m 以上**，台子上还能走。
- **竹篱院子**（`PandoraFence`，约 x ∈ [16, 86]、z ∈ [-14, 27.4]）已经有一圈能挡住车的篱笆。Peter 的边如果会穿过院子，就在 `clearances` 里把那段拿掉，不往院子中间插木栏杆。
- **海岛说明** x ∈ [-95.6, -73.8]、z ∈ [74.9, 96] 基本是海，不围。

Peter 的栏杆 `scale` 是 6（大约 6.7m 一块、3.2m 高）。大圈用大件，避免根数爆炸。相邻矩形重合的边只铺一次。须翊恒那条仍是 `scale` 2、`overlap` 0.95，周长点算法没改，还是 **140** 根。

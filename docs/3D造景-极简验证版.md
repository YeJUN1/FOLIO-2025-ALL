# 苏州园林 · 极简验证版（快速测试方案可行性）

> 本篇是 [3D造景.md](./3D造景.md) 的**最小可行简化版**。
> 目标只有一个：**用最少的资产、最短的时间，把整条流水线跑通一遍**，
> 验证「混元3D → Blender → GLB → Scene JSON → 程序拼装」这条路在你的项目里能不能走通。
>
> 不追求好看，不追求完整，只追求**跑通**。

---

# 一、和完整版相比，砍掉了什么

| 完整版 | 极简验证版 | 砍掉理由 |
|---|---|---|
| 18m × 14m 园林 | **6m × 6m 一角** | 一个镜头就够验证 |
| 约 30 个模型 | **只生成 3 个模型** | 逐件生成很慢，先验证 1 件的 quality |
| 4 类资产（建筑/石景/植物/道具） | **只做 A 类（独立物体）** | 建筑模块拼接、地形水面留给下一轮 |
| 水池 / 地形 / 石板路 | **一块平面 + 一个颜色** | 引擎自带，不占验证工作量 |
| 植物实例化 / Foliage | **不做植物** | 植被系统和大方案可行性无关 |
| 5 层景深构图 | **不构图** | 验证阶段看不出构图问题 |
| 灯光 / 雾 / 水 / 后处理 | **一盏平行光 + 环境光** | 只保证"能看见" |

# 二、验证场景：一个 6m × 6m 的角落

```text
6m
┌──────────────────┐
│                  │
│   太湖石 ▲       │
│                  │
│   月洞门 ○ ── 白墙│  ← 白墙不用模型，用一个 Box 刷颜色即可
│                  │
│        亭子 ⌂    │
└──────────────────┘
```

三样东西：**月洞门、太湖石、亭子**，各生成一次。
地面是 Plane，白墙是 Box，相机固定一个 3/4 视角——这就是全部场景。

# 三、只需要 3 条混元3D Prompt

沿用完整版的"资产规格书"写法，但都缩到最小：

**1. 月洞门**
> 中国苏州园林月洞门，独立建筑构件，高2.2米，直径2米，白色粉墙中开圆形门洞，墙厚0.25米，完整独立物体，无背景无地面，真实比例，适合游戏环境资产。

**2. 太湖石**
> 苏州园林太湖石，独立景观石，高约1.5米，瘦皱漏透，天然灰白石灰岩，多孔洞侵蚀纹理，无底座无植物无地面，完整独立物体，真实比例。

**3. 亭子**
> 苏州园林四角小亭，独立建筑，高3米，占地2.5米见方，木柱黛瓦翘角，底部平整，完整独立物体，无背景无地面，真实比例。

> 验证目的：确认 AI 生成的**比例、Pivot、网格质量**是否达到可用标准——
> 这三点任何一点不合格，整个大方案都要重新设计，所以必须最先测。

# 四、Blender 检查只留 3 步

完整版有 6 步，验证版只做最致命的 3 步：

```text
① Apply Scale（1 单位 = 1 米，用尺子量亭子柱高对不对）
② Pivot 移到模型底部中心（否则程序摆放永远浮空/入地）
③ 导出 GLB（确认纹理被打包进去，文件 < 5MB）
```

面数优化、Mesh 清理、材质重建全部跳过——垃圾堆能跑通就说明流水线通，
质量问题留到验证成功后再解决。

# 五、Scene JSON：最小版本

就按完整版第十二节的格式，但只有 3 个对象：

```json
{
  "scene": "GardenMVP",
  "objects": [
    { "asset": "moon_gate.glb",  "position": [-2, 0,  1],   "rotation": [0, 90, 0] },
    { "asset": "taihu_rock.glb", "position": [ 0.5, 0, 0],  "rotation": [0, 37, 0] },
    { "asset": "pavilion.glb",   "position": [ 2, 0, -1.5], "rotation": [0, -45, 0] }
  ]
}
```

加载逻辑（对应本项目写法）：

```text
读取 JSON
 ↓
用 ResourcesLoader / GLTFLoader 逐个加载 GLB
 ↓
按 position / rotation 摆进 Scene
 ↓
地面 Plane + 白墙 Box 用引擎几何体直接创建
```

> 本项目已有外部 GLB 集成流程（资源注册 / 材质转换 / 物理落地），
> 验证时按该流程接入即可，正好一并验证这套流程对新资产是否通用。

# 六、验证通过 / 失败的判定标准

**跑一遍就知道答案的检查清单：**

- [x] 混元3D 能否稳定产出结构完整、无大面积破面的单体模型？——✅ 3/3 一次成功（500k 面档，每次 4 候选）
- [x] 模型进 Blender 后，实际尺寸是否接近 1 单位 = 1 米？（偏差 > 30% 说明规格书 prompt 要重写）——❌ 偏差 -27%~-68%，prompt 控制尺寸不可靠，由 process.js normalize 归一化生效兜底
- [x] GLB 导出后能否被引擎直接加载？纹理是否需要额外处理？——✅ 纹理打包在 GLB 内，引擎直读无需处理
- [x] Pivot 规范执行后，`position.set(x, 0, z)` 是否让模型自然落地？——✅ 全流程自动化（免 Blender），射线贴地 + fixed 刚体对位通过
- [x] Scene JSON 驱动拼装的代码，能否复用到 30 个资产的正式场景？——✅ Garden.js 数据驱动，零代码改动接入 3 个资产

**任何一项失败** → 修该项，不要急着扩场景。
**全部通过** → 恭喜，回到完整版 [3D造景.md](./3D造景.md)，从"第三类：模块化建筑"开始扩充。

预计耗时：**半天到一天**（3 个模型生成 + 半小时 Blender + 半小时接场景）。

---

# 七、验证成功后的扩充顺序（衔接完整版）

按风险从高到低逐项加回来：

```text
第 1 步  模块化白墙/直廊/转角廊   ← 验证"拼接"可行（完整版第三节）
第 2 步  水面 + 不规则 polygon    ← 验证引擎水方案（完整版第四节）
第 3 步  植物 Instancing          ← 验证性能（完整版第五节）
第 4 步  构图 + 灯光 + 雾         ← 才轮到画面质量（完整版第十四节）
```

每一步都是独立验证点，任何一步有问题都不会废掉前面的成果。

# 八、验证结果（2026-10-01 首轮真实跑通）

**结论：5 项检查全部通过，可进入扩充阶段。**

| 检查项 | 结果 | 备注 |
|---|---|---|
| 结构完整性 | ✅ | 月洞门/太湖石/亭子 3/3 一次生成成功，结构完整、无大面积破面 |
| 内建尺度（1 单位 = 1 米） | ⚠️ 偏差大，被 normalize 兜底 | 原模型高：月洞门 ≈0.72m、太湖石 ≈1.10m、亭子 ≈0.95m（目标 2.2 / 1.5 / 3.0m）；AI 对「真实比例」的回应不可靠，规格书 prompt 控不住尺寸，必须依赖归一化缩放（1.37~3.15 倍） |
| GLB 加载与纹理 | ✅ | 3×4096² PNG PBR 直接打包在 GLB 内，引擎直读 |
| Pivot 落地 | ✅ | 压平层级 → 归一化缩放 → Pivot 归零底面中心；物理射线贴地 + fixed 刚体对位验证通过 |
| Scene JSON 拼装复用 | ✅ | 运行时 3 items 位置/旋转与 scene.json 完全一致，控制台零错误 |

**与原始验证方案的差异：**

- **Blender 手动 3 步全部省去**，由 `scripts/hunyuan/process.js` 自动化完成（压平层级 / 归一化缩放 / Pivot 归零 / 纹理打包）；
- **文件体积未达 <5MB 目标**：原始 GLB 47~56MB、Draco 压缩后 31~38MB（4K PNG 纹理占大头）；上线前建议补 KTX2 纹理压缩；
- **本轮由官网网页版通道产出**（云 API 积分耗尽）：3d.hunyuan.tencent.com 文生3D → 下载 GLB → resources/hunyuan-raw/，state.json 标记 `engine:'web'`；与 API 通道产物共用同一套 process.js 流程；
- 游戏内实际摆放使用 scene.json 的 origin [29, 0, -45] + 三个 objects，物理落地在 terrain 上通过射线完成。

**过程中修复的流水线缺陷（已记入《项目记忆库》2.1.2 / 2.1.3）：**
1. process.js 原「包装子节点命名 physical」方案无效——THREE 的 gltf.scene 名取自 glTF 场景名，且游戏碰撞体只扫描模型直接子节点；已改为命名场景本身（`scene.setName('<key> physical fixed')`）+ cuboid 直接挂场景，太湖石碰撞体复验通过。
2. 三资产材质撞名（混元导出默认名均为 `Material.001`）触发游戏材质缓存串用——三个模型全部显示为第一个资产的贴图（运行时 material.uuid / map.uuid 完全相同）；已在 process.js 增补「材质唯一命名」步骤（`setName('<key>')`），复验三者各自贴图正确（月洞门白墙灰瓦 / 太湖石灰白石质 / 亭子木架黛瓦）。
